# Week 4 observations

## Task 1
8개 패킷의 selective-repeat 슬라이딩 윈도를 선택했다. 순서 역전을 버퍼로 처리하고, ACK 손실로 재도착한 데이터에는 다시 ACK하되 출력에는 한 번만 추가한다. 손실은 재전송을 필요로 하고 중복은 중복 제거를 필요로 한다.
2,000바이트의 최소 데이터 전송은 250개인데 seed 246/999에서 각각 310/311개(1.240/1.244배)를 전송했다. ACK까지 포함하면 598/593회이며, 패킷별 ACK를 쓰는 무손실 기준 500회의 1.196/1.186배다.
두 기본 seed에서 IDENTICAL이며, 서로 다른 바이트열과 30% 손실·30% 중복·50% 재정렬을 적용한 210개 추가 전송도 종료·일치했다. 기본 검증 데이터는 같은 난수 바이트를 반복하므로 별도 난수열 검증으로 순서 오류를 추가 확인했다.

## Task 2 — 두 번째 시간대 실측 대기
경로 B의 공식 trace에서 SYN/SYN-ACK/ACK는 #1/#2/#3, 실제 ISN은 4236649187/1068969752다. SYN의 MSS=1460, WS=6(64배), SACK 허용이며, 양쪽이 별도 ISN을 선택하면 이전 연결의 지연 패킷과 혼동하거나 다음 번호를 쉽게 예측하는 문제를 줄인다.
클라이언트 #3의 수신 윈도는 2058×64=131712 B다. 업로드 방향에서는 서버가 광고한 173824 B에 비해 #145의 최대 미확인 데이터가 75296 B로 작아 그 시점의 수신 윈도는 병목이 아니며, ACK/RTT·혼잡 윈도·응용 공급량의 영향은 가능하나 캡처만으로 하나를 확정할 수 없다. 공식 교재의 Mac Firefox→gaia 서버 alice.txt 업로드이고 본인 트래픽이 아니다.
KT Wi-Fi의 2026-10-13 저녁 5회는 중앙값 48.79 Mbps, 범위 38.64–53.63 Mbps(중앙값 대비 폭 30.7%), 연결시간 중앙값 10.74 ms다. 한 네트워크만 가능해 당일 21:30 재측정을 예약했으며 아직 비교는 미완료이고 약 80분 간격은 매우 다른 시간대라는 요건에 부족할 수 있다. RTT 증가 시 ACK 기반 slow start가 느려지고 같은 cwnd에서 cwnd/RTT가 감소하지만, 현재 표본으로 인과관계는 단정하지 않는다.

## Task 3
고정 윈도는 986.75 packets/1000 slots를 전달하지만 손실 37.4%, 재전송 2340회, 평균 큐 8.79로 공유 링크에 낭비와 지연을 만든다. 구현은 974.25(기준의 98.73%), 손실 2.10%, 재전송 84회, 평균 큐 4.64025로 strong 기준을 만족한다.
처음에는 ACK마다 +1로 증가하고, 손실 이후에는 ACK마다 0.1/cwnd 증가·손실 시 0.65배 감소한다. 한 윈도 분량의 ACK를 기다리는 회복 구간으로 동일 혼잡의 연속 타임아웃에 중복 감소하지 않으며, 마지막 1000 ACK에서 윈도는 22.36–26.45로 RTT×용량=20에 소규모 큐가 더해진 범위다(영구 고정 수렴은 아님).
backoff를 0.5→0.65→0.8로 완화하면 goodput은 934.25→974.25→977.75로 증가하지만 평균 큐는 3.53→4.64→6.67, 손실은 1.70%→2.10%→3.17%로 늘었다. 0.8은 큐 기준을 위반해 0.65를 선택했다.
